# הנחיות לעבודה על חדר הבקרה (לקלוד או ל-Claude Code)
קרא את המסמכים האלה לפני כל שינוי, ועבוד רק לפיהם:
1. `dashboard/FUNCTIONAL_SPEC.md`: **מה** קיים ומה הוא עושה. מחייב בכל עיצוב.
2. הסקיל `maayanotecha-staff-ui`: **איך** זה נראה. זו מערכת העיצוב.
3. `dashboard/DESIGN_SYSTEM.md`: יומן החלטות העיצוב לחדר הבקרה מעל הסקיל (ומתחתיו ארכיון של העיצוב הקודם, לעיון בלבד).
4. `dashboard/STAFF_UI_HANDOFF.md`: תהליך ההטמעה הנוכחי, צעד אחר צעד.

## הכלל המרכזי
- **האפיון לא דורס את מערכת העיצוב, ומערכת העיצוב לא דורסת את האפיון.**
- **סתירה ביניהם:** עוצרים, שואלים את זלמן עם 2 אפשרויות (בבחירה מרובה), ורושמים: שינוי פונקציה באפיון (סעיף 11), שינוי מראה ב-DESIGN_SYSTEM.md.
- **לא מכריעים לבד,** גם כשנראה ברור.

## מקור האמת
- **הקוד:** הארטיפקט "חדר הבקרה" ב-claude.ai, בקישור https://claude.ai/artifact/CjnUchP5knm4L8EZAzWh4Z. קוראים אותו עם כלי Artifact (read).
- **הנתונים:** מסד הנתונים של אותו ארטיפקט, דרך ArtifactData. ארטיפקט חדש = מסד ריק, ולכן **מפרסמים תמיד לאותו קישור.**
- **Claude Code שרץ מקומית:** אין לו כלי Artifact. עובדים על עותק מקומי, ואת הפרסום עושים מסשן של Claude ב-claude.ai, עם אותו קובץ ולאותו קישור.

## איך עובדים
- **לא מוחקים ולא מסתירים פונקציה** בלי אישור של זלמן.
- **גיבוי:** שומרים עותק של הגרסה המפורסמת לפני כל שינוי.
- **מסך אחד בכל פעם:** מיפוי → אישור → בנייה → צילום מסך → אישור → המסך הבא.
- **לפני פרסום:** משווים מזהים, פונקציות וקישורים לגרסה הקודמת, ומריצים את סעיף 8 באפיון.
- **אחרי כל החלטה:** מעדכנים את FUNCTIONAL_SPEC.md (סעיף 11) או את DESIGN_SYSTEM.md.
- **תמונות:** מייצרים ב-fal לפי `references/fal-imagery.md` של הסקיל, אחרי שמראים לזלמן רשימה. אייקוני ממשק תמיד וקטוריים.
- **שפה:** עברית, אמ;לק בהתחלה, בלי חנופה, ומסמנים סתירות.
